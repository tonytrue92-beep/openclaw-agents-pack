# Дизайн: объединённый платный установщик + Windows-интерфейс (Companion)

**Дата:** 2026-06-06
**Статус:** утверждён Антоном (дизайн), ожидает вычитки спеки → план реализации

---

## 1. Контекст и цель

Сейчас платный клиент запускает **две** команды: сначала движок
(`openclaw-factory`), потом агентов (`openclaw-agents-pack`). Клиентов,
которые ставят «только движок» отдельно как продукт, **больше нет** — все
платные берут движок + команду агентов. Две команды = лишнее трение и
типовая путаница («а вторую запустил?», `command not found` между шагами).

**Цель:**
1. **Одна команда** на всех платных. Что поставится — решает **тариф в
   токене** (SUB / STD / VIP).
2. Для **Windows**-клиентов дополнительно предлагать официальный нативный
   **интерфейс** (OpenClaw Windows Hub / Companion) — трей-приложение,
   командный центр, диагностика, без терминала.

---

## 2. Решения (подтверждены Антоном)

- **Тариф решает** (не флаг):
  - `SUB-…` → только движок (+ main-агент).
  - `STD-…` → движок + 3 агента (Base).
  - `VIP-…` → движок + 8 агентов + база знаний (Pro).
- **Архитектура склейки:** factory остаётся точкой входа и в финале сам
  дотягивает agents-pack (approach 1). Минимум переделок, репо раздельные.
- **Windows-интерфейс:** предлагать **всем** Windows-клиентам (платным и
  тест-драйву). Способ — **открыть страницу загрузки** в браузере (с
  согласия), как мы открываем opencode.ai. Авто-запуск .exe не делаем.

---

## 3. Фича 1 — объединённый платный установщик (mac / Linux)

### 3.1. Поток (одна команда)
1. Клиент запускает **команду factory** (она становится единственной
   платной командой).
2. factory принимает/просит токен → парсит тариф (уже умеет:
   `COURSE_TIER`, regex `^(VIP|STD|SUB)-`) → кэширует в
   `~/.openclaw/course-token` (chmod 600).
3. Ставит движок + main-агент + модель (opencode-ключ) + Telegram — как сейчас.
4. **Финал — развилка по `COURSE_TIER`:**
   - **SUB** → стоп. Финальный экран «движок готов» (как сейчас).
   - **STD / VIP** → factory докачивает и запускает bundled-установщик
     агентов **в той же сессии**:
     ```bash
     bash <(curl -fsSL https://github.com/tonytrue92-beep/openclaw-agents-pack/releases/latest/download/install-agents-bundled.sh) \
       --course-token "$COURSE_TOKEN"
     ```
     agents-pack перепроверяет токен (тот же Ed25519-ключ), из префикса
     ставит `VIP_MODE`, разворачивает 3 (STD) или 8 + база знаний (VIP).

### 3.2. Почему это надёжно
- **Та же сессия терминала** → nvm уже загружен в процесс factory (он
  вызывает `openclaw` во время установки), значит у дочернего bundled-скрипта
  `openclaw` уже в PATH. Ошибка `command not found` между шагами исчезает
  физически.
- Токен передаётся **явно** `--course-token` + он же лежит в общем кэше
  `~/.openclaw/course-token` — двойная подстраховка.

### 3.3. Обработка ошибок
- Чейн оборачиваем так, чтобы **успех движка не зависел от докачки**:
  если `curl`/bundled упал (сеть / CDN-лаг `releases/latest`) — factory
  **не падает**, печатает:
  > «Движок установлен. Чтобы доустановить агентов, выполни:
  > `bash <(curl -fsSL …/install-agents-bundled.sh)`»
  (это сегодняшняя команда шага 2 как ручной fallback).
- `set -euo pipefail`: вызов агентов изолировать (`|| { warn …; }`),
  чтобы ненулевой код не ронял финал.

### 3.4. Границы (что НЕ тянет агентов)
- **Demo**, **симуляция** (`--dry-run`), **VPS-гайд** — никогда не чейнятся.
- Чейн только в **реальной установке** при `COURSE_TIER ∈ {STD, VIP}`.
- На `--vps` (Linux-сервер) чейн допустим (agents-pack работает на Linux);
  bundled + `--course-token` пробрасываем как обычно.

### 3.5. Совместимость
- Скрытый флаг **`--engine-only`** — отключает чейн (отладка / переустановка
  движка / edge). SUB и так = только движок.
- Старые **отдельные** команды продолжают работать (перезапуск,
  `--refresh-templates`, ручной fallback). Меняется только то, что бот
  теперь шлёт **одну** команду.
- Ключ Ed25519, payload-префиксы, кэш токена — **без изменений**.

### 3.6. Ограничение по платформам
Фича 1 — для **mac / Linux**, где движок ставит наш bash-factory. На
**Windows** движок ставится нативно (.exe), а агенты — через Git Bash;
там объединения «одной bash-командой» нет (это возможная будущая волна,
напр. через managed-WSL-gateway Companion). Windows-клиент платно: native
движок + agents-pack в Git Bash + предложение Companion (Фича 2).

## 4. Фича 2 — Windows-интерфейс (Companion GUI)

### 4.1. Что это
**OpenClaw Windows Hub** (репо `openclaw/openclaw-windows-node`) —
официальная нативная связка для Windows: трей-приложение (WinUI 3),
командный центр, настройки подключения/пэйринга, диагностика. Раздаётся
готовым `.exe` (build не нужен), пререквизит — WebView2 (есть на
современных Win10 20H2+/11).

Ссылки **проверены, живые (HTTP 200)** в релизе `openclaw/openclaw` 2026.6.1:
- Страница загрузки (давать клиенту): `https://docs.openclaw.ai/platforms/windows`
- Прямые ассеты (бэкап): `…/releases/latest/download/OpenClawCompanion-Setup-x64.exe`
  (и `-arm64.exe`, `OpenClawCompanion-SHA256SUMS.txt`).

### 4.2. Где живёт
В **platform-aware финале** (есть с wave 19/28) двух установщиков:
- `openclaw-agents-pack/scripts/install-agents.sh` — финал.
- `openclaw-test-drive/scripts/install-trial.sh` — финал (Windows-ветка есть с wave 33).
Factory не трогаем (на Windows движок не через factory).

### 4.3. Поведение
1. Определяем ОС = Windows (Git Bash: `uname -s` ∈ `MINGW*/MSYS*/CYGWIN*`,
   либо `$OS == Windows_NT`).
2. Предлагаем (опционально, y/N):
   > «🪟 Хочешь удобный интерфейс для Windows? Трей-иконка, командный центр,
   > диагностика — без терминала. Это официальное приложение OpenClaw.»
3. При согласии — открыть **страницу загрузки** в браузере
   (`start "" "https://docs.openclaw.ai/platforms/windows"` в Git Bash;
   обернуть platform-aware open-хелпером). Показать прямые .exe-ссылки и
   напоминание про SHA256 как текст — на случай, если браузер не открылся.
4. Без согласия — пропустить, ничего не делать.

### 4.4. На живую проверку (помечено, не блокер)
Companion цепляется к gateway по WebSocket (pairing/connect/probe). Нужно
вживую убедиться, что он подключается к тому gateway, который ставит наш
Windows-поток. Это — задача на тест (см. §7), сам факт «предложить скачать»
безопасен уже сейчас.

## 6. Верификация

**Локально (до PR), по каждому затронутому репо:**
1. `bash -n` всех правленых скриптов.
2. `shellcheck -S warning` (с нашими стандартными `-e`).
3. `bash scripts/smoke-test.sh` — включая новые asserts.
4. factory: smoke-сценарии — STD/VIP финал зовёт agents-pack; SUB/demo/sim/dry-run — нет.
5. `update-checksums.sh` → SHA256SUMS свежий (CI freshness).
6. agents-pack: `build-bundle.sh` + `bash -n dist/…-bundled.sh`.

**CI / релиз:**
7. Ветка → commit → PR → дождаться зелёного CI → merge.
8. agents-pack: тег `vYYYY.MM.DD` → bundled-релиз (иначе чейн скачает старое).

**Живой тест (чистая машина):**
9. mac/Linux, **VIP-токен**: одна команда → движок + 8 агентов + база
   знаний, без ручного второго шага, без `command not found`.
10. mac/Linux, **STD** → движок + 3 агента. **SUB** → только движок.
11. Сбой докачки агентов (отключить сеть после движка) → факт.: движок
    стоит, показан fallback, скрипт не упал.
12. **Windows** (платно и тест-драйв): в финале предложен Companion, по
    согласию открылась страница загрузки; Companion подключился к gateway
    (см. §4.4).

## 7. Передать технарю (бот `@AITeamVIPBot`)

Код установщиков делаем мы; на стороне **бота** нужно:

1. **Одна команда вместо двух.** После выдачи токена бот шлёт **единственную**
   команду — factory, с уже подставленным токеном (клиент не вводит токен руками):
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/tonytrue92-beep/openclaw-factory/main/scripts/demo-install.sh) --course-token <ВЫДАННЫЙ_ТОКЕН>
   ```
   - Для **VIP/STD** этого достаточно — установщик сам доставит агентов.
   - Для **SUB** — та же команда (движок), агенты не ставятся.
   - **Убрать** из сообщений «теперь запусти вторую команду …».
2. **Windows-подсказка (опц.):** в Windows-инструкции бота добавить строку
   «в конце установщик предложит удобный интерфейс (Companion) — соглашайся».
3. **Тест-драйв** — без изменений в команде (она и так одна), но остаётся
   действующий блокер: бот должен выдавать TRY-токен после оплаты Prodamus.

Бриф для бота создаётся при реализации:
`openclaw-agents-pack/handoff/unified-install-command-bot-brief.md` + обновить
`handoff/STATUS-FOR-TECHIE.md` (одна команда теперь).

## 8. Out of scope (сейчас НЕ делаем)
- Объединение Windows-потока «одной командой» (возможная будущая волна
  через managed-WSL-gateway Companion).
- Слияние репозиториев factory + agents-pack в один.
- Любые правки токен-ключа / payload / тест-драйв-логики (кроме Windows-offer
  в финале).
- Реальная интеграция Companion в наш CI (он — апстрим, мы только ссылаемся).

## 9. Риски
- **CDN-лаг `releases/latest`** у agents-pack: после merge нужен тег, иначе
  чейн скачает старый bundled. Митигирование: релиз-тег в чек-листе (§6.8).
- **Companion ↔ gateway** на Windows: не подтверждено вживую (§4.4) — до
  теста подаём как «официальное доп. приложение», не как обязательный шаг.
- **Чейн в той же сессии**: если у клиента движок стоял НЕ через nvm
  (редко), PATH мог отличаться — fallback-команда (§3.3) закрывает кейс.
