# Дизайн: выбор агентов при установке Pro (сколько и каких)

**Дата:** 2026-06-09
**Статус:** дизайн согласован Антоном, ожидает вычитки спеки → план рядом

---

## 1. Цель
Сейчас Pro ставит **все 8 агентов** разом (и просит 8 бот-токенов). Дать
клиенту выбрать, **сколько и каких** агентов поставить (2, 3, 5, …). Бонус:
меньше агентов = меньше бот-токенов = ниже флуд-риск Telegram.

## 2. Решения (подтверждены Антоном)
- **Способ выбора:** нумерованный список + ввод номеров через пробел (`1 3 5`).
  Пустой ввод (Enter) = **все 8**.
- **Охват:** только **Pro** (VIP, 8 агентов). **Base** не трогаем — остаётся
  фиксированные 3 (Технарь/Маркетолог/Продюсер).
- Дефолт/обратная совместимость: где меню не показываем — ставим всех 8.

## 3. Дизайн

### 3.1. Новая функция `select_pro_agents()` (в `scripts/install-agents.sh`)
Вызывается **только при `VIP_MODE=true`**, **после** подтверждения тарифа/токена
и **до** R2 (запрос бот-токенов). Результат — переопределяет `AGENTS_TO_INSTALL`
выбранным подмножеством. R2 (бот-токены) и R4 (создание агентов) уже итерируют
`AGENTS_TO_INSTALL` — их менять НЕ нужно.

### 3.2. Меню
```
   Каких агентов поставить? (Pro — до 8)
     1) 🔧 Технарь        5) 🧭 Координатор
     2) 📈 Маркетолог     6) ✍️ Копирайтер
     3) 🎬 Продюсер       7) 💰 Лидоруб
     4) 🎨 Дизайнер       8) 🎥 Контент-агент
   Введи номера через пробел (напр. 1 2 7) — или Enter, чтобы поставить всех 8:
```
Порядок номеров фиксирован = порядок VIP-массива
`tech marketer producer designer coordinator copywriter leadcloser content`.
Уже установленные агенты помечаются `✓` (для повторного запуска).

### 3.3. Парсинг ввода
- Пусто → все 8.
- Токены = числа 1–8 → дедуп, сортировка, отбор соответствующих id.
- Невалидный ввод (буквы / вне 1–8 / ничего валидного) → перепрос **один раз**;
  при повторной ошибке → все 8 (не блокируем установку).
- Минимум 1 агент (пустой результат после парсинга = все 8).
- После выбора — подтверждение: «Поставлю: 🔧 Технарь · 📈 Маркетолог · 💰 Лидоруб
  (3). Дальше попрошу 3 бот-токена.»

### 3.4. Гейты (меню НЕ показываем → ставим всех 8)
- Не интерактив: `[[ ! -t 0 ]]` (CI/headless).
- Задан `--only <agent>` (явный single-режим — как сейчас).
- `--install` (автоматизация / пропуск меню).
> При объединённом потоке (factory дотягивает agents-pack) установка идёт в
> интерактивном TTY той же сессии → меню **показывается** клиенту. Это желаемо.

## 5. Out of scope
- **Base** (остаётся фикс 3).
- **Tier-гейтинг** (Pro-агенты только по VIP-токену) — без изменений.
- Мульти-`--only` (`--only a,b,c`) — возможная будущая опция для автоматизации; сейчас не нужно.
- R2/R4 — не трогаем (итерируют `AGENTS_TO_INSTALL`).
- Изменения в боте/factory — не требуются (меню внутри agents-pack).

## 6. Тестирование
- smoke (grep): `select_pro_agents` определена; вызывается под `VIP_MODE`;
  список из 8 id; Enter→все; не-TTY→все.
- `bash -n`, shellcheck, `bash scripts/build-bundle.sh` + `bash -n dist/...`,
  `update-checksums.sh`.
- Живой: Pro-установка → меню → ввод `1 2 7` → ставятся 3 агента, просит 3 бот-токена.
- Релиз: тег после merge (bundled пересобирается).

## 7. Риски
- **Парсинг ввода** (bash 3.2): аккуратно с `read` + word-splitting по пробелам;
  невалидный ввод не должен ронять `set -euo pipefail`.
- **Повторный запуск:** пометка `✓` для уже стоящих — определять по наличию
  агента/воркспейса; если детект не сработал — не критично (существующая логика
  не дублирует агентов).
- **Координатор без команды:** если клиент возьмёт только Координатора —
  оркестрировать некем; это его выбор, не ломается. (Опц. подсказка — не делаем.)
