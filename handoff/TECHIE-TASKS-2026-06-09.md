## 1) 🔴 БЛОКЕР — выдача TRY-токена после оплаты (тест-драйв)
Тест-драйв ставится только по `TRY`-токену; сейчас бот их не выдаёт → продукт не продать.

Формат: `TRY-<hash16>-<tg_id>-<подпись_b64url>`
- `hash16` — 16 hex UPPERCASE (из order_id/рандома)
- `tg_id` — Telegram ID клиента
- подпись — Ed25519, base64url **без padding**, **тот же ключ**, что для VIP/STD/SUB

Подписываем строку: `TRY|<hash16>|<tg_id>`
```js
function makeTryToken(tgId, orderId, privateKeyPem) {
  const hash16 = /* 16 hex UPPERCASE из orderId/рандома */;
  const payload = `TRY|${hash16}|${tgId}`;
  const sig = crypto.sign(null, Buffer.from(payload,'utf8'), crypto.createPrivateKey(privateKeyPem));
  return `TRY-${hash16}-${tgId}-${sig.toString('base64url')}`;
}
```
Поток: кнопка оплаты → Prodamus → webhook (проверить HMAC) → success_url → deep-link в бота → бот выдаёт TRY-токен и шлёт команду (п.2).

## 2) Одна команда установки (платный поток объединён)
Бот шлёт **ОДНУ** команду с подставленным токеном:
- `VIP-/STD-/SUB-` →
  `bash <(curl -fsSL https://raw.githubusercontent.com/tonytrue92-beep/openclaw-factory/main/scripts/demo-install.sh) --course-token <ТОКЕН>`
  (SUB = только движок; STD = +3 агента; VIP = +8 агентов)
- `TRY-` →
  `bash <(curl -fsSL https://raw.githubusercontent.com/tonytrue92-beep/openclaw-test-drive/main/scripts/install-trial.sh) --token <TRY-ТОКЕН>`

Убрать «теперь запусти вторую команду» — второй команды больше нет.

## 3) Аналитика установок — бот шлёт `/issue` с email
При выдаче ЛЮБОГО токена (email знает только бот, из Prodamus):
```
POST <WORKER_URL>/issue
Headers: X-Admin-Key: <ADMIN_SECRET>,  Content-Type: application/json
Body: {"token_hash":"<sha256(полный_токен) hex>", "tg_id":"<tg_id>", "email":"<email>", "tier":"VIP|STD|SUB|TRY"}
```
Хэш строго: `hashlib.sha256(token.encode()).hexdigest()` (весь токен целиком).
Fire-and-forget — если `/issue` не ответил, выдачу токена НЕ блокируй.

## 4) 🔴 Отозвать токены прошлого потока (НЕ трогая ручные)
Деактивируй в базе бота токены/доступы **прошлого потока**, чтобы бот их больше
не признавал и не выдавал команду установки.
- **Ручные токены не трогать** (комп-доступы, команда, тесты) — должны работать.
- Признак «поток vs ручной» определи по своей БД (дата/поле «поток»/партия
  импорта/флаг источника).
- **ОБЯЗАТЕЛЬНО:** сначала dry-run / выгрузка списка на отзыв → согласовать с
  Антоном, что ручные в него НЕ попали → только потом применять.
- Нюанс: установщик проверяет подпись **локально**, серверной revocation нет.
  Деактивация в боте отрезает выдачу/перевыдачу (команду берут только у бота),
  но не аннулирует уже сохранённый кем-то токен. Жёсткий отзыв (ротация
  Ed25519-ключа + перевыпуск актуальных) — отдельно, по запросу.
