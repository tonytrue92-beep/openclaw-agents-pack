# Бриф технарю — аналитика установок (хостишь ТЫ + бот шлёт /issue)

> ⚠️ **Обновление 2026-06-10:** Cloudflare НЕ используем (решение Антона).
> Эндпоинты аналитики хостишь **ты на своём сервере** — логично рядом с
> Prodamus-webhook, который ты и так поднимаешь для TRY-токенов.

## Зачем
Видеть **кто и сколько ставил + email + тариф + версия + ОС**. Установщик
email **не видит** — он есть только у бота (из оплаты Prodamus). Поэтому
данные склеиваются из двух источников по `sha256(токена)`:
бот шлёт `/issue` (с email) при выдаче токена, установщик клиента шлёт
`/activation` при установке.

## Часть 1 — подними 3 эндпоинта (у себя)
**Готовая логика — в [`analytics-endpoint-reference/`](./analytics-endpoint-reference/)**
(reference-worker.js: обычный HTTP + 3 SQL-запроса, переносится на
Express/FastAPI/что угодно; schema.sql — таблица `installs`).

| Метод/путь | Кто зовёт | Auth | Тело |
|---|---|---|---|
| `POST /issue` | твой бот | `X-Admin-Key: <секрет>` | `{token_hash, tg_id, email, tier}` |
| `POST /activation` | установщик клиента | без ключа | `{token_hash, tg_id, installer_version, client_os, tier, track}` |
| `GET /stats` | Антон | `X-Admin-Key` | — (`?format=csv`) |

Правила (в референсе уже реализованы): `/activation` обновляет только
`/issue`-нутые строки (мусор игнор); `/issue` идемпотентен (UPSERT);
CSV экранирует formula-injection.

**Когда поднимешь:** пришли Антону URL (`https://…/activation`) — он
подставит его в установщики (1 строка, переменная `VIP_ACTIVATION_ENDPOINT`,
сейчас пустая = пинг выключен). Секрет `X-Admin-Key` сгенерируй сам, отдай
Антону для `/stats`.

## Часть 2 — бот шлёт /issue при выдаче токена
При успешной выдаче токена (после оплаты) бот шлёт один POST:

```
POST <ТВОЙ_URL>/issue
Headers:
  X-Admin-Key: <твой секрет>
  Content-Type: application/json
Body:
  {
    "token_hash": "<sha256(token) hex>",
    "tg_id": "<tg_id_клиента>",
    "email": "<email_из_Prodamus>",
    "tier": "VIP"        // или STD / SUB / TRY — по выданному токену
  }
```

## Хэш токена — строго так (иначе склейка с установкой не сойдётся)
```python
import hashlib
token_hash = hashlib.sha256(token.encode()).hexdigest()   # 64 hex-символа
```
Хэшируется **полный токен целиком**, как он выдан клиенту
(`VIP-<hash16>-<tg_id>-<sig>` и т.п.). Тот же алгоритм используют установщики —
не меняй регистр/обрезку, иначе строки не сойдутся.

## Важные детали
- **Fire-and-forget:** если `/issue` не ответил — НЕ блокируй выдачу токена,
  просто залогируй ошибку. Аналитика вторична по отношению к продаже.
- **Не слать сырой токен** — только хэш (токен = фактический ключ установки).
- **TRY-токены тоже регистрируй** (`tier:"TRY"`) — увидим воронку тест-драйва.
- (Опц., разово) прогнать `/issue` по старым выданным токенам из БД — тогда
  и прежние клиенты попадут в отчёт с email.

## Как проверить
Выдай себе тестовый токен → `curl -s "<URL>/stats" -H "X-Admin-Key: <секрет>"`
→ строка с твоим email/tg_id/tier; после установки заполнятся
`activated_at`, `installer_version`, `client_os`.
