### Wave 21 — главное меню (только что задеплоено)

Сразу после ASCII-баннера показывается:

```
   ╔════════════════════════════════════════════════════════╗
   ║                  Г Л А В Н О Е   М Е Н Ю               ║
   ╚════════════════════════════════════════════════════════╝

   Что ставим?

     1)  Pro        — 8 агентов (полный набор)  ← рекомендуется
     2)  Base       — 3 базовых агента
     3)  OpenClaw   — только движок (без агентов)
```

Это «витрина → корзина → оплата» — клиент видит линейку продуктов
сразу, потом подтверждает токеном. UX как у магазина.

**Если выбран OpenClaw** → graceful exit без запроса токена (движок
уже стоит из factory).

**Если выбран Pro/Base** → запрос токена → валидация tier vs выбор:
- Pro+VIP-токен → OK, 8 агентов
- Pro+STD-токен → red-block «нужен Pro-токен»
- Base+STD/VIP → OK, 3 агента (Pro→Base downgrade разрешён)
- Base+SUB → red-block

V_MAIN **пропускается** если есть флаги `--install` / `--course-token`
/ `--only-agent` / `--config` / `--vps` (для CI и продвинутых
сценариев).

## 📋 Общие правила работы

1. **Версионирование**: каждая правка → bump `INSTALLER_VERSION` →
   commit → PR → review → merge. Я обычно мержу за Антона если CI
   зелёный — но для крупных правок (типа SUB-tier) лучше Антон сам.

2. **Smoke-test обязательно**: `bash -n` + локальный smoke-test
   перед push. CI отловит большинство багов, но локальный быстрее.

3. **SHA256SUMS**: если правишь скрипты — `bash scripts/update-checksums.sh`
   перед коммитом. Иначе CI job «SHA256SUMS freshness» зафейлится.

4. **Backwards-compat**: токены / payload / Ed25519-ключи / внутренние
   `tier`-имена (STD/VIP/SUB) — **никогда не меняем**. Меняем только
   что **клиент видит**.

5. **Когда закрыл задачу** — пиши Антону одной строкой:
   ```
   Wave NN готов, версия X.Y.Z, PR #N в main
   ```
   Антон обновит этот status-документ.
