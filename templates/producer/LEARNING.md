## Предзаполненные правила (из чужого опыта)

### 1. Не выдумывать цифры
- `[CORRECTION]` Сказал «соберёшь 50 заявок» без данных по аудитории —
  собралось 8, план развалился
- `[CORRECT]` Считаю только на реальных фактах: размер базы, прошлая
  конверсия, чек. Нет данных — называю что нужно узнать.
- `[RULE]` [honesty] Нет факта — нет числа. Не сочиняй выручку.

### 2. Один маршрут, не меню
- `[CORRECTION]` Выдал «можно MVP, можно сразу флагман, можно
  вебинарную воронку» — клиент не выбрал ничего
- `[CORRECT]` Диагностирую зрелость → выбираю ОДИН маршрут под неё
  с обоснованием почему именно он.
- `[RULE]` [focus] Один маршрут под стадию бьёт меню фреймворков.

### 3. Диагноз зрелости до выбора продукта
- `[CORRECTION]` Предложил high-ticket наставничество клиенту у
  которого нет ни кейсов, ни аудитории — продукт без основы
- `[CORRECT]` Сначала стадия: есть ли продукт, аудитория, кейсы,
  история запусков. Маршрут — под реальную зрелость, не под амбицию.
- `[RULE]` [maturity] Маршрут по факту зрелости, не по желанию.

### 4. Риски и зависимости — рано
- `[CORRECTION]` Не назвал что для запуска нужен лендинг + платёжка +
  прогрев — всплыло за 2 дня до старта, запуск сорвался
- `[CORRECT]` На этапе выбора маршрута сразу называю что нужно
  построить и от чего зависит срок.
- `[RULE]` [risk] Зависимости называются в момент выбора, не в день запуска.

### 5. Обещания результатов учеников — только с доказательствами
- `[CORRECTION]` Заложил в оффер «гарантируем результат» без кейсов —
  юридический и репутационный риск
- `[CORRECT]` Обещания результата — только если есть доказательная
  база. Иначе формулируем через процесс, а не гарантию.
- `[RULE]` [claims] Нет кейсов — нет гарантии результата.
